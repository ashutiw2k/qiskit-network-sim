**Stabilizer works for the tested unchanged depolarizing model and the separately routed calibration-derived alternative. The measured simulation speedups were 1.72× and 1.17× respectively.** These results cover one small local example, not the full production workload or the reported five-minute versus thirty-minute jobs. All work was isolated here; protected-file verification is in [integrity_check.json](integrity_check.json).

**What the repository does.** [generate_jobs.py](../../cloud_runs/generate_jobs.py) enumerates simple graph paths. [run_job.py](../../cloud_runs/run_job.py) chooses one manifest item, uses the graph's node count to allocate code wires plus a path wire for every possible node pair, then calls the selected code's encoder, SWAP chain, and sink syndrome circuit. The graph's latency, distance, and inferred channel parameters do not enter this simulation. The source node is encoded, data wires are sequentially swapped through each shared edge wire, and sink ancillas measure stabilizers. This is gate-level simulation of an abstract network path.

[common.py](../../cloud_runs/common.py) instantiates packaged `FakeBrisbane`, `FakeTorino`, `FakeFez`, or `FakeMarrakesh`; it does not request live IBM calibration or execute a QPU job. It transpiles against a gate-name list only, without a backend target, coupling map, initial physical layout, or routing policy. Abstract wire numbers therefore select one-qubit calibration entries by numerical coincidence. They are not established IBM physical assignments. A wire beyond the snapshot's qubit range has no corresponding local one-qubit noise entry. The native two-qubit name is `ecr` for Brisbane and `cz` for the other backends.

The default `depolarizing` model attaches:

- Local `sx`, `x`, `rz`, and `id` depolarizing channels where the target reports positive error. It passes reported `error` directly as Aer parameter lambda. For one qubit this gives average infidelity **r/2**, not the reported r. Experiment A intentionally preserves this behavior.
- One all-qubit depolarizing channel on the selected native two-qubit gate. The default lambda is `0.01`, corresponding to average infidelity **0.0075**. This is uniform across pairs and does not preserve IBM pair-specific gate errors. Construction is already a single all-qubit call; `num_circuit_qubits` no longer controls an all-pairs construction loop.
- No readout error, relaxation, idle-time decoherence, or calibrated reset errors. Zero-calibration virtual RZ operations are ideal. Unsupported names or uncalibrated one-qubit indices can remain ideal.

The other checked-in mode, `thermal`, calls `from_backend(gate_error=False, readout_error=False, thermal_relaxation=True)`. It models duration/T1/T2 relaxation where the factory has entries, including resets where durations are available; it is **not the complete default backend noise model**. Since the circuit is not physically routed, backend-local two-qubit channels often do not match. In this example, **49/56 CZ occurrences receive no thermal channel**. Its noise contains `kraus` instructions and is excluded from stabilizer comparison. Thermal simulation was not timed, and the user's thirty-minute observation was not independently reproduced.

**Experiment and measured performance.** The read-only `Code513` and circuit builder produced a two-node path `[0,1]`, logical input `0`, with 19 wires, 15 active wires, four syndrome bits, and source depth 32. Source operations are H, Z, CX, CZ, SWAP, reset, measure, and barriers. All tested compiled rotations were integer multiples of pi/2 within floating-point precision. **Syndromes and statistical limits.** Displayed count keys are `c3 c2 c1 c0`; `ci` corresponds to `Code513.STABILIZERS[i]`: XZZXI, IXZZX, XIXZZ, ZXIXZ. Histograms retain the existing order `0000` through `1111`. Routing maps source syndrome ancillas 14,15,16,17 to physical qubits 27,26,25,22 while preserving their classical destinations. Source, A, and B ideal controls each yielded `{'0000': 64}`. This checks the chosen input/path and bit mapping, not arbitrary-state equivalence. No decoder or px/py/pz inference was added.

The original timing repeats incremented job seeds by one. Aer [uses the circuit seed plus the shot index](https://github.com/Qiskit/qiskit-aer/blob/0.17.2/src/simulators/circuit_executor.hpp), so these runs reused nearly all shot streams. Repetitions 1 and 2 are excluded from distribution statistics. Future harness runs space seeds by 10,000 and the analysis checks intervals for overlap. With **128 independent shots per engine**, the 5,000-permutation two-sample TV test gives A: TV 0.1797, p=0.0988; B: TV 0.1406, p=0.8570. Neither rejects equal distributions at 5%; **equivalence remains statistically inconclusive**. Timing repeats do not manufacture additional statistical evidence.

**What the alternative preserves.** B uses the FakeFez snapshot shipped in IBM Runtime 0.44.0, last updated **2025-02-26 15:16:25−05:00**. The exact JSON files and hashes are saved. It maps all 19 abstract wires to an explicitly recorded connected patch and uses the backend Target with SABRE routing and seed 1729. This is supported single-device physical routing for the small example, not a calibration assignment for real distributed network links. The larger production circuits and other codes/backends remain unvalidated.

The requested `NoiseModel.from_backend(..., thermal_relaxation=False)` was constructed and inspected. In these versions its Target supplies only a scalar readout error, causing symmetric readout matrices. B instead uses the public `NoiseModel.from_backend_properties(backend.properties(), gate_error=True, readout_error=True, thermal_relaxation=False)` factory, preserving asymmetric readout probabilities from the same snapshot. The behavior is documented by the [versioned factory source](https://github.com/Qiskit/qiskit-aer/blob/0.17.2/qiskit_aer/noise/device/models.py), and the measured differences are saved in [readout_factory_audit.json](results/readout_factory_audit.json).

Coverage validation establishes:

- All **266 CZ** occurrences match supported physical tuples and have calibrated channels. The 35 ordered tuples contain **20 distinct pair-error values**, ranging from 0.0021389144 to 0.0149206102. There are no silently ideal two-qubit interactions.
- All **496 SX** occurrences preserve the relevant **20 distinct qubit-error values**, ranging from 0.0001320305 to 0.0007640689. The 66 RZ occurrences remain ideal because their reported errors are zero. Four resets remain ideal because reset-error calibrations are missing and thermal relaxation is disabled; this is an explicit omission.
- For every used noisy SX/CZ tuple, the channel's calculated average infidelity matches the reported r within 1e-10. The factory already applies **lambda = d*r/(d−1)**, d=2**n. The harness independently compares its channels against this formula; it does not convert factory output a second time. [Aer defines lambda as the depolarizing parameter](https://qiskit.github.io/qiskit-aer/stubs/qiskit_aer.noise.depolarizing_error.html).
- Each measured physical qubit retains both `P(measured 1 | prepared 0)` and `P(measured 0 | prepared 1)`. For example, qubit 27 uses 0.001953125 and 0.0087890625, rather than replacing both by their mean 0.00537109375.

Accurate wording is: **“A calibration-derived depolarizing and readout approximation using the packaged IBM FakeFez snapshot, preserving the reported gate-error values for the physical operations used and the per-qubit asymmetric readout probabilities, with thermal relaxation disabled.”** Here gate-error values are interpreted as average infidelities by Aer. Disabling thermal relaxation removes explicit duration-dependent T1/T2 relaxation, excitation/decay, and idle decoherence. The model also omits coherent errors, leakage, crosstalk, temporal correlations/drift, correlated readout, and a physical network-channel model. A two-qubit depolarizing channel does include its own two-qubit Pauli terms; that is not evidence for measured crosstalk. This is not the complete physical noise of an IBM QPU.
